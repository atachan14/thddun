# thddun の docs

## 目的
Task の親子階層、前提関係(先に終わらせる Task)、担当者ごとの状態を分けて管理し、ボードと関係図で見る。

本来の用途は、自分と AI が使うこと。ポートフォリオとして公開する可能性もある。

## 作り直しの方針(2026-11-05 決定)
- **まずローカル版を作る。** 保存先は kb のような Markdown と Git で、DB は使わない。理由: 以前の試作で DB が必要になった主な理由は、複数人の権限・ログイン・同時編集で、自分と AI だけなら要らないため。
- **公開版は、あとから同じコアに保存先と入口を足して作る。** 別のアプリを2つ作るのではなく、コアは1つにする。最初の公開版は、ブラウザだけで動くデモ(架空のサンプルを使い、編集は見る人のブラウザに保存)が候補。本当の共有版は、必要になったら作る。
- **最初から、すべての操作に「誰が操作したか」(自分か、どの AI か)を持たせる。** 権限を確かめる入口も必ず通す(ローカル版では全部許可)。理由: あとから権限を足すとき、すべての読み書きを直さずに済むため。
- kb(`G:\kb`)の表示にも使えると便利そう。kb の中身は、公開版やデモに入れない。
